# Deploy Studio on Railway

Studio pins AgentTree Core **0.2.2** at immutable commit `1f9649e4f9c10bc38defdf1e3fef70bebf95df99`. Both Dockerfiles build from this repository alone. See [the audit](railway-deployment-audit.md) and verify the final deployment gate before creating Railway services.

## Services

Use three Railway services in one project: **Postgres**, **Backend**, and **Frontend**. Connect the same Studio GitHub repository to Backend and Frontend. Keep each service's root directory at the repository root, so Docker `COPY` paths work. In each service's Variables or Build settings, set `RAILWAY_DOCKERFILE_PATH` to `backend/Dockerfile.railway` or `frontend/Dockerfile.railway` respectively. Railway's custom Dockerfile path and root-directory rules are documented in [Dockerfiles](https://docs.railway.com/builds/dockerfiles) and [monorepo deployment](https://docs.railway.com/deployments/monorepo).

1. Create a Railway project and add PostgreSQL. Do not expose PostgreSQL publicly.
2. Add the Backend service from the Studio GitHub repository. Set the Dockerfile path above. Attach a Railway Volume at **`/data`** before starting the service; set `AGENTTREE_STUDIO_ARTIFACT_ROOT=/data/artifacts`. Railway [mounts volumes at runtime](https://docs.railway.com/volumes), so migrations run at process startup rather than in a build or pre-deploy hook.
3. Set Backend variables from [`.env.railway.example`](../.env.railway.example). Set `DATABASE_URL` to the Postgres service's Railway reference variable (`${{Postgres.DATABASE_URL}}` if the service is named Postgres). Set `AGENTTREE_STUDIO_DEPLOYMENT=railway`, a stable Fernet key, explicit bootstrap Admin username/password, `AGENTTREE_STUDIO_SECURE_COOKIES=true`, and the frontend's final HTTPS origin. Generate the Fernet key once with `python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'` and store it in Railway Variables and a secure backup. **Changing this key makes existing encrypted provider Secrets unreadable.** Never put it in Git or logs.
4. Configure Backend's internal listening port as **8000** (`PORT=8000` if necessary). Keep Backend private unless external Public API clients need a public domain. Set its healthcheck path to `/api/system-health`. Startup runs `alembic upgrade head` before Uvicorn; FastAPI startup verifies the schema and performs one-time Admin bootstrap. Do not use multiple backend replicas with the current in-process Run coordinator.
5. Add Frontend from the same repository and set its Dockerfile path above. Set `BACKEND_INTERNAL_URL=http://<actual Backend private DNS name>:8000` and `PORT=8080`. Railway's [private networking](https://docs.railway.com/guides/docker-compose) provides the actual `<service>.railway.internal` name. Generate a public HTTPS domain for Frontend. Copy its exact origin, without a trailing slash, into Backend's `AGENTTREE_STUDIO_PUBLIC_ORIGIN`, then deploy/redeploy both.
6. Open the Frontend HTTPS URL. Verify `/api/system-health` through the Frontend domain, log in with the one-time bootstrap credentials, and change the password immediately. Existing Admin credentials are never reset by changing bootstrap variables. Provider API keys are entered through Studio's encrypted Secret/Provider UI, not Railway variables.
7. Create a dedicated friend account with **User** role, only the permissions needed for test Trees/Runs, and explicit grants to test Trees. Do not give Admin access. Prefer a dedicated low-quota test ProviderConnection. Share only the Frontend HTTPS URL and that account's temporary credentials through a suitable private channel.
8. In the browser, verify provider administration, Tree editor, a Test Run, Live View and SSE updates, durable artifact fetch, and logout/login. Verify Public API V1/V2 separately if needed, using a personal API key. Never put such a key in the browser URL.

The frontend serves a production Vite build and proxies `/api` on the same origin. Nginx disables buffering for SSE; provider secrets, cookies, and API keys are not compiled into the frontend bundle. The backend's Public API browser CORS allowlist is optional; leave `AGENTTREE_PUBLIC_API_CORS_ORIGINS` empty for this same-origin setup. Do not use `*` with credentials. Persist both PostgreSQL and the artifact volume, and back them up together.

The backend remains process-local for active Core execution. A backend restart interrupts active Runs and Studio reports recovery unavailable; restart does not resume Core checkpoints. Use one backend instance until durable Core recovery is integrated. Verify Railway ingress SSE timeout and reconnect behavior on the actual domain before friend testing.
